Algorithm Parallel Ant Colony Optimization (PACO)
Input:
	instance — VRP instance containing:
		Customers: array of customer nodes with demands
		Dist: n×n distance matrix
		Vehicles: number of available vehicles
		VehicleCapacity: vehicle capacity constraint
	cfg — configuration object containing:
		BaseConfig: base ACO configuration with:
			NumAnts: total number of ants to distribute across workers
			Iterations: maximum number of iterations
			Alpha, Beta, Evaporation, Q, InitialPheromone, EliteWeight, Seed parameters
		NumWorkers: number of parallel workers
		NumExchanges: number of synchronization checkpoints (≥ 1)
Output:
	solution — best feasible solution shared via global_best during periodic exchanges
	If no feasible solution exists, return solution with infinite cost

1. Handle degenerate case
	If length(instance.Customers) = 0 then
		Return Empty-Solution(cost = 0)  
	If instance.Vehicles = 0 then
		Return Infeasible-Solution()  
2. Validate configuration and instance
	Call Apply-Config-Defaults(cfg.BaseConfig)
	If NOT Validate-Instance(instance) then
		Return Infeasible-Solution()
3. Normalize worker configuration
	num_workers ← Normalize-Worker-Count(cfg.NumWorkers, cfg.BaseConfig.NumAnts)
	num_exchanges ← Resolve-Exchanges-Count(cfg.NumExchanges)
4. Prepare shared execution state
	ants_per_worker ← Split-Ants(cfg.BaseConfig.NumAnts, num_workers)
	global_best ← Infeasible-Solution()
	exchange_interval ← max(floor(cfg.BaseConfig.Iterations / num_exchanges), 1)
5. Run workers in parallel
	For each worker w from 0 to num_workers - 1 do concurrently
		5.1 Create worker-local configuration
			local_cfg ← copy of cfg.BaseConfig
			local_cfg.Seed ← cfg.BaseConfig.Seed + w × 1000
			local_cfg.NumAnts ← ants_per_worker[w]
		5.2 Initialize worker-local state
			rng ← Create-RNG(local_cfg.Seed)
			τ_local ← Initialize-Pheromone(length(instance.Dist), local_cfg.InitialPheromone)
			best_local ← Infeasible-Solution()
		5.3 Iterate independently
			For iter = 0 to local_cfg.Iterations - 1 do
				ants ← empty list
				For ant = 0 to local_cfg.NumAnts - 1 do
					solution, feasible ← Build-Solution(instance, τ_local, local_cfg, rng)
					add solution to ants
					If feasible AND solution.cost < best_local.cost then
						best_local ← Clone-Solution(solution)

				If (iter + 1) mod exchange_interval = 0 then
					Synchronize access to global_best
					If best_local.cost < global_best.cost then
						global_best ← Clone-Solution(best_local)
					shared_best ← Clone-Solution(global_best)
				Else
					shared_best ← Infeasible-Solution()

				Call Evaporate(τ_local, local_cfg.Evaporation)

				For each solution in ants do
					If solution.cost > 0 then
						amount ← local_cfg.Q / solution.cost
						Call Deposit-Solution(τ_local, solution, amount)

				If best_local.cost < +∞ AND best_local.cost > 0 then
					elite_amt ← local_cfg.EliteWeight × local_cfg.Q / best_local.cost
					Call Deposit-Solution(τ_local, best_local, elite_amt)

				If shared_best.cost < +∞ AND shared_best.cost > 0 AND shared_best.cost < best_local.cost then
					share_amt ← local_cfg.EliteWeight × local_cfg.Q / shared_best.cost
					Call Deposit-Solution(τ_local, shared_best, share_amt)
			Store best_local as the worker's local result
6. Wait for all workers to finish
	Wait-For-All-Workers()
7. Return global best solution
	If global_best.cost = +∞ then
		Return Infeasible-Solution()
	Return global_best

Function Split-Ants(total, workers):
Input:
	total — total number of ants to distribute
	workers — number of parallel workers
Output:
	distribution — array of size workers where distribution[i] is ant count for worker i
Algorithm:
1. Compute base and remainder
	base ← total / workers (integer division)
	remainder ← total mod workers
2. Distribute evenly with remainder to first workers
	For i = 0 to workers - 1 do
		distribution[i] ← base
		If i < remainder then
			distribution[i] ← distribution[i] + 1
3. Return distribution
	Return distribution

Function Normalize-Worker-Count(requested, available_ants):
Input:
	requested — user-specified worker count (0 means auto)
	available_ants — number of ants for distribution
Output:
	normalized — valid worker count
Algorithm:
1. Auto-detect if not specified
	If requested ≤ 0 then
		requested ← Number-Of-CPUs()
2. Cap by available ants
	If requested > available_ants then
		requested ← available_ants
3. Ensure at least 1
	If requested ≤ 0 then
		requested ← 1
4. Return
	Return requested

Function Resolve-Exchanges-Count(requested):
Input:
	requested — user-specified number of exchange checkpoints
Output:
	normalized — valid exchange checkpoints count
Algorithm:
1. Apply default for invalid input
	If requested ≤ 0 then
		Return 10
2. Return provided value
	Return requested

Information Exchange Pattern:
1. Exchange interval calculation:
	- Divides total iterations into num_exchanges equal checkpoints
	- Each worker checks at every exchange_interval iterations
	- Avoids continuous synchronization overhead
2. Exchange mechanism (periodic synchronization):
	- Worker updates global_best if its best solution is better
	- Worker retrieves current global_best as shared_best
	- Worker reinforces pheromone with shared_best if beneficial
	- All workers synchronize at same iteration checkpoints

Synchronization Pattern:
1. Master thread (main execution):
	- Calculate exchange_interval based on Iterations and NumExchanges
	- Create configuration and distribute to workers
	- Launch one worker per parallel unit
	- Wait for all workers to complete
	- Return the shared global best solution
2. Worker thread (parallel execution):
	- Receive local configuration and ant count
	- Initialize local pheromone matrix and RNG
	- Execute local ACO algorithm independently
	- At each exchange checkpoint:
	  * Check if (iteration + 1) is divisible by exchange_interval
	  * Synchronize shared-best state
	  * Update global_best if local best is better
	  * Retrieve current global_best as shared_best
	  * Reinforce local pheromone with shared_best (if beneficial)
	- Store local best in worker result slot
	- Signal completion
3. Key properties:
	- No shared pheromone matrix (each worker has local copy)
	- Independent random seeds to avoid correlation
	- Global best is shared during execution (not only at end)
	- Synchronization happens at periodic exchange intervals
	- Communication overhead is controlled via NumExchanges parameter

	Notes:
		- Empty-instance handling: workers and solver treat zero-customer instances as solved with cost 0; non-empty instances with zero vehicles remain infeasible and return +∞.
	- Numerical stability: implementations should use ε when distances are zero or computed weights become non-positive (suggested values: ε = 1e-9 for distances, ε = 1e-12 for attraction weights).
